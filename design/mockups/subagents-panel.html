CHOSEN · A
Drill-in, flat panel

The list replaces itself with the agent. The detail is the panel itself: no nested card, no box-in-box — one header row, hairline sections, and the agent's own content on the pane background.

  • Roster shows model + effort (and tokens/tools) on every row, so agents are identifiable before opening.
  • Preview first: prompt/result clamp to 3–4 lines with “Show full”.
  • Borders only where they separate: section hairlines and tool rows; nothing wraps the agent.
OPTION B
Accordion stack

One list; expanding a row reveals the detail nested underneath it, indented on a connector rail with a “SUBAGENT DETAIL” label.

  • Best continuity: previous agents stay visible while reading one.
  • No navigation: everything happens in place.
  • Tradeoff: a long agent makes the column tall; tools collapse behind “Show N more”.
OPTION C
Split list + detail

A slim agent column on the left, detail on the right with Overview / Tools / Messages segments and a metrics grid.

  • Fastest switching: selection is always visible, good for 10+ agents.
  • Most like the rest of the app: reuses the pane’s tab/segment language.
  • Tradeoff: the narrowest text column (≈340px).
Shared across all three: running/completed/error come from structured stream events (system/task_started·task_updated·task_notification), not from the launch text, so a finished Claude Code agent never stays “running”; subagent tool calls render inside the agent and are removed from the main thread; prompt and result are always preview-first with an explicit expand control; the thread card stays a one-line entry point.
